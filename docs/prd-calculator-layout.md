対象アプリ：Mahjong Score Calculator App（麻雀の点数計算アプリ）
関連文書：`docs/spec-000-アプリ全体.md`（現行仕様の正）、前PRD `prd-next-improvements.md`

作成日：2026-11-28（たたき台）

## 0. 本書の位置づけ

- 本書は、2026-11-27にKTNが発案した電卓式レイアウトを、本体へ取り込むためのPRDである。
- 原則として、PRDに記載されていないことは「やらないこと」ではない。また「絶対に変えてはならないルール」でもない。実装やQAに伴い、より良いアイデアが生まれた場合は都度相談し、柔軟に対応するものとする。
- 設計は実験場「Calculator Button Lab」で検証しながら固め、2026-11-28にKTNが「機能、ボタンの種類、配置全部これで」と確定した。**迷ったときの正はラボの実装**とする。
- 先行実験の「Calculator Layout Mock」（表つきモック）は、ラボに役割を引き継ぎ、2026-11-28にお焚き上げ（削除）した。モックだけが持っていた仕様のうち正しいもの（スマホの早見表ルール、§3.5）は本書に取り込んである。
- 実装の詳細仕様は、各タスク着手時に GitHub Issue として切り出し、本PRDと spec-000 を参照する。各チケットでは spec-000 の改訂と回帰テストの追随もセットで行う。
- 注意：ラボは未公開である（本体は GitHub と公開リンクで公知だが、電卓画面の意匠はKTNとClaudeの間だけにある）。ラボの公開リンクを気軽にばら撒かないこと。

## 1. 背景・目的

現行アプリは「入力（カード1）が上、結果（カード2）が下」（スマホ表示）で、結果を見るために視点が上下する。KTNの発案は、電卓にならって **結果ディスプレイを最上部に固定し、入力ボタンをその下に集める** こと。

- 入力するたびに上の数字がパッと変わる「入力→即フィードバック」のループを、スマホの親指操作に合わせる。
- 目標は、**入力モードがファーストビューに収まる「ガチの電卓」**（390×844 程度の画面を目標とする）。早見表・スコアシートは参照・記録モードのため、完全収納は求めない。
- 計算ロジックは変えない。変えるのはレイアウト、操作部品の種類と配置、および付随する新機能（モード、テーマ切替、スコアシート）である。

## 2. 対象範囲・対象外

対象範囲：

- スマホ表示・PC表示の画面構成の全面入れ替え（§3）
- 操作部品の変更：三状態トグルスイッチ化、2パネル分離（便利パネル／計算パネル）、モード計器ストリップ、テーマ切替の新設
- スコアシート機能の新設（§3.6）
- 文言の変更：「入力Clear」→「Clear」、「満貫切り上げ」→「満貫切上げ」（§3.2・§3.3）
- 「骨格は固定、中身だけ変わる」原則（§5）と「配置と構成は両デバイス共通」原則（§5.5）

対象外：

- 点数計算ロジックの変更（計算結果は一切変えない。#6の順番制御・自動移動、#11のTIPS、満貫切上げの計算上の扱いは現行通り引き継ぐ。§4）
- 3人麻雀対応、ホームページ化、カメラ画像解析（従来の step 49+ 計画で別途扱う）

## 3. 画面構成（確定）

### 3.0 全体の骨格

- 電卓の全部品（ディスプレイ、便利パネル、計算パネル、入力パッド）は **1枚のカード** の中に入る。
- 並び順は上から：ディスプレイ → 便利パネルA → 計算パネルB → 入力パッド（符・翻）。
- PC表示：左に電卓カード（画面幅の約1/3）、右にパネルエリア（約2/3）。右パネルは電卓カードの高さに影響されず、内容が長い場合はパネル内部のスクロールで完結する（電卓が連れ伸びしない）。
- スマホ表示：電卓カードが画面の主役となり、モードに応じてパッド部分が入力／早見表／スコアシートに入れ替わる（§3.2）。
- **ヘッダーは置かない（廃止）**。PC・スマホとも1画面に収まる前提の設計であり、固定ヘッダーは不要（タイトルと入力Clearを担っていた現行ヘッダーは、Clear の便利パネルへの移動とともに役目を終える）。
- **フッターは表記を残して固定を解除**する。文言「© 2026 R.KTN — Built with Muse」はそのまま、画面下部の固定バーではなくページ末尾の通常フッターとして置く。

### 3.1 ディスプレイ（結果表示・最上部）

- 条件（例：子・ロン・25符・2翻）を上部に、**点数を左下、満貫以上の役名を右下**（金色・明朝）に表示する。全体は少し下寄せに詰める。
- 入力が未完了のときは、点数欄に「―」を表示し、「まずは 親 / 子 を選んでください」のような次の一手のヒントを出す。
- 内訳は、便利パネルAの「内訳」ON/OFFスイッチ（初期値OFF）で表示する。ONのとき計算の内訳（式と支払い明細）がディスプレイの真ん中に出て、点数と役名は下部の定位置に残る。別パネルは置かない。
- ディスプレイの高さは固定する（ラボでは 12rem。内訳を収めるため、モック時代の 11.5rem から拡大）。結果⇄内訳の切替や、未入力→入力済みの変化で、ディスプレイの高さも下の要素の位置も動かさない（§5）。

### 3.2 便利パネルA（ディスプレイ直下）

画面に対する操作（表示の都合）を集めたパネル。並びは次の通り。

- **モード切替（計器ストリップ）**：選択肢が隙間なくつながった分割ボタン。選択中が分かる見た目にする。
  - スマホ：3モード「入力／早見表／スコアシート」。パッド部分の表示が入れ替わる。
  - PC：2モード「早見表／スコアシート」。右パネルエリアの表示が入れ替わる（電卓は常時表示のため「入力」は無い）。
  - 切り替えても入力状態・計算結果は保持する。
- **内訳 ON/OFF スイッチ**（§3.1）。
- **テーマ切替（ライト／ダーク）**：新設。タップでアプリ全体の配色が切り替わる。初期状態は端末（OS）の設定に連動し、スイッチ操作はそれを上書きする。
- **Clear ボタン**：文言は「Clear」（「入力Clear」から改名）。動作は現行の入力Clearと同じ（全選択をクリアし、満貫切上げも OFF に戻す）。

### 3.3 計算パネルB（入力パッドの直上）

計算の条件を決める操作を集めたパネル。

- **親／子 三状態トグルスイッチ**、**ロン／ツモ 三状態トグルスイッチ**。
  - 三状態：未選択（null）はノブが中央にあり、両ラベルとも無色。ラベル側をタップして選択し、選択後はタップするたびに左右が入れ替わる。未選択に戻るのは Clear のときだけ。
  - 選択側のラベルは、選択中ボタンと同じ緑で強調する。
  - #6 の順番制御はそのまま効く（親／子を選ぶまでロン／ツモは操作できない、等。§4）。
- **満貫切上げスイッチ**：表記は「満貫切上げ」（「満貫切り上げ」から変更）。置き場所は本パネル（当初決定 2-C「コントロール列に置く」を、2パネル化に伴い計算パネルへ更新）。#2 のルール（常時表示・対象外はグレーアウト・ON は保持・Clear でのみ OFF）は維持し、切上げ ON 時の早見表の「満貫」表記も現行通りとする。

### 3.4 入力パッド

- **符カードを左、翻カードを右に、同幅で横並び**。各カードの中は縦2列のグリッド。
  - 符：ラベル「符」をグリッドの1マス目に埋め込み、20はその右隣から流し込む（11個＋ラベル＝12マス＝6行）。
  - 翻：ラベル「翻」をグリッドの1マス目に埋め込み、1はその右隣から流し込む（13個＋ラベル＝14マス＝7行。13は「13+」表記）。
  - ラベルは枠も背景もないプレーンな文字で、ボタンと間違えない見た目にする。ロック中は一緒に淡くなる。
  - 符6行と翻7行は、行の高さを均等配分してカードの高さを揃える。
- 密度はラボの調整を正とする（数字は大きめ、余白は詰める。ただしタップしにくくならない最小サイズは保つ）。**サイズ・幅の最終微調整は未決（§8）**。

### 3.5 早見表

- 本実装の表は、ラボの簡略版ではなく、**現行アプリの正式な表**（カード4＝1〜4翻の表、カード5＝満貫以上の表）を使う。以下、1〜4翻の表を「表A」、満貫以上の表を「表B」と呼ぶ。
- PC表示：右パネルエリアに、**1枚のカードの中に表A（上）と表B（下）を区切り線を挟んで両方とも常時表示**する。表の下の注釈は付けない。ハイライトは現行通り（表Aでは選択セル、表Bでは結果が5翻以上のときに該当する役の行）。
  - ※現行仕様（Issue #5）との差分：PCでは「対象以外の表を非表示にする」ルールを改め、両表常時表示とする。
- スマホ表示（早見表モード）：**計算結果と符合する表だけを表示する**（モック由来のルール。Issue #5 の考え方と同じ）。
  - 結果が1〜4翻（3・4翻の満貫を含む）→ 表Aだけ。結果が5翻以上 → 表Bだけ。
  - 結果が未確定（入力途中・未選択・Clear直後）→ 両方の表を表示する。
- 表の見出しは付けない（条件はディスプレイに出ているため）。表のセルは改行禁止とし、行の高さを均一にする。注記を出す場合は固定の高さの枠を常時確保し、注記の有無で高さを変えない（§5）。

### 3.6 スコアシート

- 対局結果をメモする表。モード切替で表示する（スマホは3モード目、PCは右パネル）。
- プレイヤー4人の名前（編集可）×対局ごとの点数を入力でき、**合計が自動計算**される。
- 行は **14行固定**とし、行ラベルは「1局目」〜「14局目」。行追加はしない。
- **内容はアプリに保存しない**（KTN決定）。ページを開いている間だけの仮メモ＋集計であり、注記で期待値を揃える。注記文はKTNの文面のまま：「スコアシートの内容はアプリに保存されません。必要に応じてスクリーンショットなどをご活用ください。」
- 入力する数値の意味づけ（点数そのものか収支か、マイナスの扱い等）の詳細は未決（§8）。スコアシートのチケットで詰める。

### 3.7 テーマ（ライト／ダーク）

- 便利パネルAのテーマ切替で手動選択できる（§3.2）。手動選択が無い場合は端末設定に連動する（現行通り）。
- テーマ選択を次回起動時まで保持するかどうかは未決（§8）。

## 4. 引き継ぐ振る舞い（本体の現行仕様から変更なし）

- **#6 ボタン制御**：親／子 → ロン／ツモ → 符 → 翻 の順にしか進めない。上の段を変えても下の段の選択は保持する（案A）。押せる／押せないボタンの見た目の差も維持する。三状態トグルにも同じ制御を効かせる（未選択＝null の状態が、順番制御の前提になる）。
- **ロジック制御の自動移動**：ツモ20符→ロンで30符へ、20／25符で1翻は2翻へ、など現行通り。
- **#11 TIPS**：選べない理由は、押せないボタン自身の上に、その理由で押せないときだけ、ホバーで表示する。注記枠は固定高さを確保し、TIPSの表示／非表示で高さを変えない。
- **計算・ハイライト**：基本点の計算式、満貫以上の役名、早見表のハイライト（答えの居場所だけに付ける、Issue #4 の原則）は現行通り。
- **変更点のまとめ**（現行仕様から意図的に変えるもの）：画面構成の全面入れ替え、親／子・ロン／ツモのトグル化、満貫切上げの置き場所（カード2右上→計算パネルB）と表記、Clear の文言と置き場所（ヘッダー→便利パネルA）、PCの表の表示ルール（#5 の非表示→両表常時表示）、テーマ切替とスコアシートの新設、ヘッダーの廃止、フッターの固定解除（Issue #3 の固定バー化を置き換える。表記は維持）。

## 5. 原則：骨格は固定、中身だけ変わる

KTNが最も強く求める原則。PRDの全項目に横串で効かせる。

- テキストの量が変わっても（改行される、TIPSが出る／消える、内訳を切り替える、モードを切り替える）、画面の骨格（各要素の高さ・位置）は動かさない。
- 手段：ディスプレイの高さ固定、注記は固定高さの枠を先に確保、表のセルは改行禁止、スイッチの状態表示は最長文言分の幅を先に確保する。
- モックでKTNが確認済み：「揺れなくなった」（2026-11-27）。

## 5.5 原則：配置と構成は両デバイス共通（2026-11-28、KTN決定）

- 部品の顔ぶれ・並び順・画面の構成は、PCとスマホで共通に1回だけ決める。デバイスごとに構成を変えない（統一感を守るため）。
- デバイス差として許すのは、大きさと密度だけ（ボタンのサイズ、余白の詰め具合）。
- 決定済みの例外（画面面積の都合によるもので、部品の顔ぶれは変えない）：モード計器ストリップの選択肢（スマホ3つ／PC2つ。PCは電卓が常時見えているため）、早見表の見せ方（PCは両表常時／スマホは符合する表だけ）。

## 7. 決定記録

- **PCも電卓式にする（1-B）**（2026-11-28、KTN）。構成は左約1/3に電卓、右約2/3にパネル（§3.0・§3.5）。
- **PCの早見表は両表常時表示**（2026-11-28、KTN）。当初の「結果が5翻以上のときだけ満貫以上の表に切り替える」は、注釈を無くして両表を縦に並べる案に置き換えた。
- **満貫切上げスイッチの置き場所**：当初 2-C「入力｜早見表＋Clear の行」（2026-11-28）を、2パネル化の確定に伴い **計算パネルB** へ更新（同日夜）。#2 のルールは維持。
- **2パネル分離**（2026-11-28、KTN発案・確定）：便利パネルA（モード・内訳・テーマ・Clear）と計算パネルB（親／子・ロン／ツモ・満貫切上げ）。均等割りはやめ、幅は機能ごとに最適化する。
- **モードは計器ストリップ、他は独立ボタン**（2026-11-28、KTN）：A〜C案の比較の末、B案（計器ストリップ）とC案（テーマ切替追加）のハイブリッドに確定。
- **スマホの早見表は符合する表だけ**（2026-11-28、KTN）：モック由来のルールを正として採用（§3.5）。
- **スコアシートは保存しない・14行固定・行追加なし**（2026-11-28、KTN。§3.6）。
- **文言**：「Clear」への改名、「満貫切上げ」表記（2026-11-28、KTN）。
- **モックの処分**：Calculator Layout Mock はお焚き上げ（削除）済み（2026-11-28）。残すのはラボのみ。
- **ヘッダー廃止・フッター固定解除**（2026-11-29、KTN）：PC・スマホとも1画面に収まる前提の設計のため、ヘッダーはもう必要ない。フッターは表記を残し、固定バーをやめてページ末尾の通常フッターにする（§3.0）。

## 8. 未決事項

1. **サイズ・幅の微調整**：部品の最終寸法は、本実装のタスクの中で実機確認しながら詰める（KTN：「サイズとか幅とかの微調整はまた追ってやる」）。
2. **スコアシートの中身の詳細**：入力する数値の意味づけ、マイナスの扱い、合計以外の集計の要否など。スコアシートのチケット（§6-5）の前に詰める。
3. **テーマ選択の保持**：テーマ切替の手動選択を、次回起動時まで保持するか（保持するなら保存の仕組みが要る。スコアシートの「保存しない」決定とは別に判断する）。
4. **タスクの切り方と順序**：§6は提案。KTNの決めた順序に置き換える。

## 9. 見送り（対応しないこととして記録する）

- **表モードでClearを押すと表の列幅がヌルっと変わる件**：モックでKTNが発見し、「今は直さなくていい」と判断したもの。本実装では列幅固定の方向で最初から作り、再発させない。
- **親／子で表の色温度を変えるアイデア**（親＝暖色・子＝寒色）：面白いが採用はしていない。アイデアメモとして残す。
